What happens when you create, start and stop a machine?

Follow the arrows. The bold heading in each box tells you who acts; the text below says what they do. First follow a successful start. Then compare what happens when something fails.

The privileged networking helper is the existing clankerd process running as administrator on your Mac. The machine process is clankerd-vmspawn, which runs the virtual machine. Neither is the short-lived vmctl CLI process.

1. You create the machine

This saves what to run. The virtual machine is not running yet. No live machine network connection is created at this step.

2. You start the machine

Read downward. The CLI first asks for networking, then launches the process that will run the machine. These are separate processes with different jobs.

XPC is macOS’s way for these processes to send requests and replies. It controls setup; the packet socket carries the machine’s network data.

3. What if startup is slow or abandoned?

This is the gap between the helper creating the connection and the machine process asking to use it.

Before the changes

An abandoned startup can leave a real network connection and firewall rules behind.

After the changes

The unused-connection leak is addressed, but a genuinely slow startup can be cut off. The current code does not automatically recover that startup.

4. What happens when you stop the machine?

The helper performs network cleanup. Saved files only retain information; they cannot remove firewall rules themselves.

Before the changes

The helper can leave actual firewall rules behind, forget how to retry through Stop, and then report success. The CLI also discards its saved connection identifier.

After the changes

A later Stop can now finish removal. But the remaining rules are not guaranteed to disappear: after the first automatic failure, another explicit Stop or successful helper restart cleanup is required.

5. What if the helper crashes during a firewall request?

This is a separate failure during network setup. A release number is needed to undo the request to keep firewall filtering enabled.

Before the changes

The macOS change and file write are separate. A crash between them can leave a request without its release number.

After the changes

The original crash gap remains. The saved flag makes uncertainty visible, but introduces another failure: a command that never starts can leave a stale flag that blocks the helper.

Charts describe the code’s intended sequence and identified failure paths. Native Mac failure and connectivity acceptance remains unverified. The displayed commands use the repository’s documented vmctl syntax.
