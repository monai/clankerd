# Native XPC serialization for clankerd-network-ipc

Researched 2026-11-14. Source inspection only; no macOS execution or implementation changes.

## Recommendation

Keep the existing public `Settings`, internally tagged `Request`, and `Response` types, and put a native XPC dictionary codec behind the transport boundary. For this small protocol, a focused codec around the existing C bridge is the lowest dependency and ownership risk. If reducing handwritten field mapping is the priority, evaluate Rama's native Serde codec in a macOS spike before adopting the entire crate. It is a real implementation, not merely a Serde dependency, but introduces Rama/Tokio dependencies and does not solve descriptor ownership.

Keep `packet_fd` outside ordinary Serde data. Receive it into `OwnedFd` immediately after a successful duplication; close it on every decode/error path. An integer serialized through Serde is an integer, not descriptor transfer. Treat unknown descriptor-bearing fields carefully: eager native-object-to-enum conversion can duplicate descriptors that ordinary Serde rejection/ignore paths never close.

## Tagged enums and ownership

The current `#[serde(tag = "action", rename_all = "snake_case", deny_unknown_fields)]` enum has struct/unit variants, which [Serde supports with internal tagging](https://serde.rs/enum-representations.html). Its native representation can remain a dictionary containing `action` and the variant's fields. Rama's map/struct and `deserialize_any` implementations suggest compatibility, but this is an inference from source, not an executed result. Verify every variant, missing/unknown fields, wrong scalar types, null options, nested settings, and malformed replies on macOS before switching transport.

Both reviewed native message enums store `RawFd`; Rama even derives `Clone` for its enum, which copies the descriptor number rather than duplicating ownership. It documents that recipients must close received descriptors. Rama's native conversion directly returns `Fd(xpc_fd_dup(...))`; the caller must also reject negative duplication results before constructing `OwnedFd`. Neither reviewed generic Serde codec models FD lifetime/transfer. These are reasons for an explicit descriptor side channel or an owning transport envelope, not reasons to avoid native XPC values entirely. [Rama message source](https://docs.rs/crate/rama-net-apple-xpc/0.4.0/source/src/message.rs), [Rama object conversion](https://docs.rs/crate/rama-net-apple-xpc/0.4.0/source/src/object.rs).

Apple specifies that [xpc_dictionary_dup_fd](https://developer.apple.com/documentation/xpc/xpc_dictionary_dup_fd(_:_:)) creates a descriptor owned by the caller, returns -1 for a missing/wrong-type entry, and requires closing it. [xpc_fd_dup](https://developer.apple.com/documentation/xpc/xpc_fd_dup(_:)) has equivalent duplication/close obligations. This differs from merely reading a scalar integer.

## What Apple recommends

Apple's C API uses native object graphs and dictionary messages; its guide explains that the XPC container supports IPC primitives such as file descriptors and warns that the underlying wire encoding is opaque and may change. Use public dictionary/object APIs rather than reimplementing or persisting the XPC wire format. The archive guide recommends the C API for applications not using Foundation. [Apple Creating XPC Services, C API discussion](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingXPCServices.html).

Apple's [current Swift tutorial](https://developer.apple.com/documentation/xpc/creating-xpc-services) uses typed Codable request/response models. This supports typed model-to-XPC serialization as a design, but does not establish an Apple-endorsed Rust library. Apple does **not** forbid a JSON string inside a dictionary in the reviewed sources. Removing that extra encoding layer is an engineering choice that preserves native type information and permits direct descriptor values; it is not a compliance requirement. No benchmark was run, so no latency or allocation improvement is claimed.
